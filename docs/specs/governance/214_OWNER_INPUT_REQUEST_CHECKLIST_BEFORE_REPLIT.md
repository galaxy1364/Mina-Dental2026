# MinaDent V1.16 — Owner Input Checklist Before Replit

**Purpose:** مشخص کردن اینکه قبل از شروع Replit چه اطلاعاتی اگر کاربر بدهد، کیفیت اجرای Phase 1 و طراحی بسیار بهتر می‌شود.

---

## 1. اطلاعاتی که اگر الان بدهی خیلی کمک می‌کند

### 1.1 نمونه طراحی

لطفاً اگر داری بفرست:

- 5 تا 20 اسکرین‌شات از بانکت/کیوبانک/بانک مهر که ظاهرش را دوست داری.
- ویدئوی کوتاه از حرکت، داک، چیپ‌ها، صفحه اصلی، sheetها.
- اسکرین‌شات از داشبورد/نوبت‌دهی/پرونده/تقویم نرم‌افزارهای دندانپزشکی که خوب یا بد هستند.

قانون: این‌ها فقط برای **استخراج pattern/token/interaction** هستند، نه کپی مستقیم.

### 1.2 داده واقعی کلینیک

اگر آماده است:

- spelling نهایی نام کلینیک
- لوگو یا تصویر سربرگ اگر داری
- spelling دقیق دکترها و لاب‌ها
- لیست اولیه خدمات درمانی و تعرفه‌ها اگر داری
- نمونه رسید/نسخه/رضایت‌نامه/فرم سوابق پزشکی
- قوانین کاری خاص مطب

### 1.3 دستگاه و مسیر تست

قبل از Replit بهتر است مشخص شود:

- قرار است preview اول در Expo Go باشد یا Development Build؟
- گوشی اندروید تست اصلی همان مسیر USB/کابل است؟
- Replit فقط executor است یا repo واقعی هم آنجاست؟
- آیا شروع از repo جدید Zero Rebuild است یا وارد repo فعلی می‌شود؟

اگر معلوم نیست، Phase 0S read-only audit باید اول جواب دهد.

---

## 2. چیزهایی که لازم نیست الان بدهی

این‌ها می‌توانند بعداً در فاز خودشان بیایند:

- credential پیامک
- credential payment
- credential Supabase production
- فایل مهر/امضا رسمی
- اتصال بیمه
- connectorهای خارجی
- کاتالوگ کامل انبار

تا وقتی credential واقعی نباشد، فقط contract/hook ساخته می‌شود، نه VERIFIED REAL.

---

## 3. سؤال‌های تصمیمی قبل از Phase 1

1. شروع code روی Replit انجام شود یا local-first و بعد Replit sync؟
2. هدف preview اول: فقط Foundation shell یا Auth+SQLite هم در همان packet؟
3. آیا می‌خواهی در اولین preview، ظاهر بانکی/داک/چیپ/داشبورد دیده شود یا ابتدا foundation فنی کاملاً ساده و بعد design؟
4. برای آنلاین بوکینگ، default policy: نمایش نام پزشک یا فقط تخصص/انتخاب داخلی؟
5. ارتودنسی در MVP inactive بماند؟

پیشنهاد فعلی: اول Replit را با read-only audit اجرا کنیم؛ بعد Phase 1 Foundation packet کوچک بسازیم.
