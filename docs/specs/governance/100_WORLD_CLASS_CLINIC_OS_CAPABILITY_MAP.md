# MinaDent V1.6 — World-Class Clinic OS Capability Map

## Purpose
MinaDent is not a simple dental app. It is a Dental Clinic Operating System. This map lists the capability domains that must exist over time.

## Core command center
- Live dashboard with today, money, appointments, lab, debts, follow-ups, sync, backup.
- Role-based dashboards for manager, secretary, doctor.
- Timeline cards and next-best-action cards.
- Alert severity and ownership.

## Patient OS
- Master patient record.
- File number, phone, national code, relationships/referrer.
- Medical history.
- Visit history.
- Dental chart.
- Imaging/files.
- Financial summary.
- Communication history.
- Journey timeline.
- Consent and legal documents.

## Smart Scheduling OS
- Jalali calendar.
- Doctor/unit/room availability.
- Appointment types and durations.
- Conflict detection.
- Free slot suggestions.
- Waiting list.
- No-show handling.
- Follow-up/recall.
- Arrival and queue flow.
- Online booking future path.

## Clinical OS
- Encounter flow.
- Chief complaint.
- Exam.
- Diagnosis.
- Treatment plan.
- Tooth-level chart.
- Prescription.
- Treatment completion.
- Lab connection.
- Follow-up.

## Finance OS
- Invoice.
- Payment.
- Debt.
- Installment.
- Cheque.
- Discount rules.
- Doctor share.
- Lab cost deduction.
- Reports.
- Audit trail.

## Lab / Implant / Inventory OS
- Lab order lifecycle.
- Due dates and delay warnings.
- Implant components and costs.
- Stock levels.
- Consumption from treatment.
- Minimum threshold alerts.

## CRM and communication OS
- SMS reminders.
- WhatsApp actions.
- Birthday/recall campaigns.
- Missed appointment follow-up.
- Debt follow-up.
- Patient journey communications.

## AI layer
- AI assistant for navigation and drafting.
- No autonomous clinical diagnosis.
- No autonomous financial/deletion/messaging actions.
- Human approval and audit mandatory.
- Semantic search and workflow suggestions future.

## System layer
- Offline-first local DB.
- Sync queue and conflict resolution.
- Audit trail.
- RBAC.
- Backup/restore.
- Monitoring.
- Release/update/rollback.
- Evidence ledger.

## Capability rule
Every accepted capability must define:
- user role
- business value
- data model
- UI state
- sync behavior
- audit behavior
- test evidence
- phone evidence
- phase ownership
