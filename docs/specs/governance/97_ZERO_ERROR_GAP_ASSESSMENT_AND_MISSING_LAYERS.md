# MinaDent V1.6 — Zero-Error Gap Assessment & Missing Layers

## Purpose
This document answers the question: "Before sending more files, what is still missing so MinaDent can be built as a zero-error, real-code, world-class, Persian-first dental operating system?"

## Non-negotiable finding
V1.5 created the core governance foundation, but MinaDent is not yet ready for coding. The missing layer is a **pre-implementation readiness pack** that converts product ambition into verifiable inputs, decisions, test scripts, and phase contracts.

## Current status
- Governance pack exists through V1.5.
- Legacy v54 documents were audited and converted into governance/backlog, not copied.
- Expo Go device constraint is locked: user phones currently support Expo Go SDK 54.
- No repo init, no build, no schema, no connector, no MCP, no package install is allowed yet.

## Remaining missing layers before safe implementation

### 1. Final input dossier
We still need a controlled place to collect all user-provided files, screenshots, design references, old code, logs, clinic rules, and competitor observations. No file should enter implementation until tagged as ACCEPT / REWRITE / REJECT / FUTURE.

### 2. Visual reference extraction
The Banqet/Bank Mehr style must be converted into tokens and patterns: layout, depth, cards, chips, sheet behavior, dock, top command/search, Persian typography, motion, states. It must never become brand/logo/color copying.

### 3. Competitor coverage matrix
Labkhand, MinaDent market products, and other dental systems must become capability rows. Every accepted feature must have a MinaDent implementation target that is stronger: offline-first, audit/RBAC, Persian/RTL/Jalali, timeline-driven, AI-human-approved, phone-tested.

### 4. Exact phase deliverable contracts
Every phase must define: files allowed, files forbidden, real-code scope, test commands, phone runtime evidence, user review checklist, rollback, and next resume point.

### 5. Phone test scripts
Because the user must see meaningful progress on phone, every valuable stage needs a short runtime script: what screen opens, what tap happens, what must appear, what screenshot/evidence proves it.

### 6. Data model completeness gate
Before schema work, the domain catalog must be complete enough for Patients, Scheduling, Finance, Lab, Dental Chart, Treatment, Implant, CRM, AI, Backup, Audit, and Sync. Missing statuses or relationships are STOP_BLOCKER.

### 7. Provider verification backlog
SMS, WhatsApp, Iranian payment, insurance, Salamat/SEPAS, push notifications, backup storage, and hosting must not be implemented from guessed APIs. Each requires official docs/API access/test credentials/legal feasibility.

### 8. AI safety and legal risk plan
AI must never make autonomous diagnosis, treatment, payment, deletion, or messaging decisions. It can draft suggestions and require human approval with audit.

### 9. Real-code acceptance rubric
Every Replit output must be scored against: production value, Persian RTL, no mock/dead actions, data contract, test evidence, device evidence, no forbidden files, and ZIP overlay integrity.

## V1.6 verdict
MinaDent needs a final pre-implementation readiness layer before repo/init. This version adds that layer.
